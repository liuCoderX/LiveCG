# 真机联调：部署与演练清单

目标：在**真实设备**上把 LiveCG 跑通并演练一遍故障处理，之后才进入正式播出。
开发阶段 CasparCG 只对过假 AMCP 服务器、计分器只对过 UDP 模拟器、主备只在同一台机器的两个进程间测过，这份清单补的就是这些空白。

用法：按顺序做，每项打勾；**验收**写的是这一项算通过的标准，不满足就记到最后的问题记录表里，不要跳过。
建议先在非直播时段完整走一遍（约半天），正式播出当天只做第 9 节的开播前检查。

---

## 0. 角色与记录

- [ ] 指定一名负责人（拿主意、决定是否接管备机）和一名记录人（填第 11 节的表）
- [ ] 准备一台能看到 PGM 画面的监视器，演练时所有「画面是否中断」都以它为准
- [ ] 记录本次联调使用的版本：LiveCG 提交号（`git log -1 --oneline`）、Node、CasparCG、OBS / vMix 版本

## 1. 设备、网络与端口

推荐拓扑（地址仅为示例）：

| 设备 | 示例地址 | 说明 |
|---|---|---|
| LiveCG 主机 A | 10.0.0.5 | 跑 LiveCG 服务 |
| LiveCG 备机 B | 10.0.0.6 | 跑 LiveCG 服务（不做主备可省略） |
| CasparCG 播出机 | 10.0.0.20 | 输出 Fill / Key 到切换台 |
| OBS / vMix 机 | 10.0.0.21 | 如果用浏览器源叠加 |
| CS2 OB 机 | 10.0.0.30 | 观察者客户端 |
| 计分器桥接 | 10.0.0.40 | 场馆计分器 → LiveCG UDP 格式 |
| 操作员电脑 | 任意 | 浏览器打开控制台 |

- [ ] 所有设备在同一制作内网，使用**固定 IP**（主备、CasparCG、CS2 cfg 都写死地址）
- [ ] 防火墙放行：

  | 方向 | 端口 | 用途 |
  |---|---|---|
  | 所有设备 → A、B | TCP 3000（或你设的 `PORT`） | 控制台、输出页、WebSocket、CS2 GSI、HTTP API、主备同步 |
  | A、B → CasparCG | TCP 5250 | AMCP 控制 |
  | 计分器桥接 → A、B | UDP 5300（或控制台里设的端口） | 计分器数据 |
- [ ] 每台机器的系统时间开启 NTP 同步（画面上的时钟不依赖系统时间，但审计记录、日志要对得上）
- [ ] **验收**：从 CasparCG 播出机、OBS 机、CS2 OB 机的浏览器都能打开 `http://10.0.0.5:3000/api/presets`

## 2. 部署 LiveCG（主机，做主备时备机同样做一遍）

- [ ] 安装 Node.js 22 或更新版本、pnpm
- [ ] 取代码并构建：

  ```bash
  git clone https://github.com/liuCoderX/LiveCG.git && cd LiveCG
  ```

  ```bash
  pnpm install && pnpm build
  ```
- [ ] 准备配置：主机复制 `deploy/primary.env.example`、备机复制 `deploy/backup.env.example` 为项目根目录的 `.env`，按文件里带 ★ 的项填写（不做主备就用 `.env.example`，主备三项留空）。服务启动时自动读取 `.env`；已经设置的环境变量（如 systemd `EnvironmentFile`）优先，空值视为没填

  | 变量 | 主机 A | 备机 B | 说明 |
  |---|---|---|---|
  | `PORT` | 3000 | 3000 | |
  | `LIVECG_DATA_DIR` | 如 `/var/lib/livecg` | 同左 | 配置、账号、审计都在这里，要能备份；需提前建好并让服务账号可写 |
  | `CS2_GSI_TOKEN` | 自定 | 与 A 相同 | 必须与 CS2 cfg 里的 token 一致 |
  | `LIVECG_ADMIN_PASSWORD` | 首次启动用 | 与 A 相同 | 不填会随机生成并强制首次修改 |
  | `LIVECG_OUTPUT_TOKEN` | 可选 | 与 A 相同 | 设置后输出页地址必须带 `&token=` |
  | `LIVECG_PEER_URL` | `http://10.0.0.6:3000` | `http://10.0.0.5:3000` | 不做主备就不填 |
  | `LIVECG_REPLICATION_TOKEN` | 至少 16 位 | 与 A 相同 | 不足 16 位服务会拒绝启动 |
  | `LIVECG_ROLE` | `primary` | `backup` | |
  | `LIVECG_CS2_CAPTURE` | 联调时填 `1` | 同左 | 录制 CS2 原始数据（见第 4 节），正式播出时留空 |
  | `LIVECG_AUTH` | **不要填** | **不要填** | 填 `off` 会关闭登录，只能在开发机上用 |

- [ ] 运行自检，处理所有 ✗（⚠ 视情况处理）：

  ```bash
  pnpm preflight
  ```

  自检会检查 Node 版本、控制台是否已构建、配置是否齐全、主备对端能否连上且复制密钥一致、每个房间的 CasparCG 能否连上、「LiveCG 地址」是不是误填了 localhost、计分器端口冲突、本机中文字体等。服务开着或关着都可以运行；问题有 ✗ 时退出码为 1，可以放进开播前的检查脚本

- [ ] 配成系统服务，崩溃自动重启：Linux 用仓库里的 `deploy/livecg.service`（文件开头有安装步骤；`pnpm` 路径用 `which pnpm` 确认），Windows 可用 NSSM 一类的服务管理工具
- [ ] 代码更新后：`pnpm install && pnpm build`，再重启服务
- [ ] 启动，确认日志里打印了 `server on http://localhost:3000` 和数据目录
- [ ] 打开 `http://10.0.0.5:3000/`，用 `admin` 登录。随机生成的初始密码在服务日志里和 `<数据目录>/initial-admin-password.txt`；改完密码后**删除这个文件**
- [ ] 在「账号与权限」给每位操作员建独立账号（导播 / 只读），需要时限定房间
- [ ] 做主备时：两台都启动后，A 的控制台顶部显示绿色「主机」，B 显示黄色「备机 · 同步中」
- [ ] 两台都配好后再跑一次 `pnpm preflight`：主备一节应显示对端在线、本机角色正确
- [ ] **验收**：重启服务进程，登录状态、播出单、配置都还在

## 3. 输出接入

### 3.1 字体（先做，否则后面的画面检查都不算数）

- [ ] 在**每台播出机**（CasparCG、OBS、vMix 所在机器）上确认装有中文字体。默认字体顺序是 HarmonyOS Sans SC → Noto Sans SC → 系统默认；如果「外观」里改了字体，播出机上也要装
- [ ] **验收**：人名条里的中文、比分条里的数字没有方框、没有明显换成宋体一类的系统字体

### 3.2 CasparCG

- [ ] 确认 CasparCG 版本为 **2.4 或更新**。输出页需要 Chromium 87 以上的浏览器内核：CasparCG 2.4.0 起内置 CEF 117，满足要求；2.2 内置的是 Chromium 63，输出页会整页空白
- [ ] 如果画面渲染异常（黑屏、闪烁、掉帧），可以尝试 CasparCG 2.4 配置里的 angle backend 设置，官方说明是「最合适的后端因模板和机器而异」
- [ ] CasparCG 的输出 consumer（如 DeckLink）按切换台要求配置 Fill + Key（外键）
- [ ] 控制台「设备 → CasparCG」（需管理员）：勾选启用，填 CasparCG 地址、端口 5250；**「LiveCG 地址」填 CasparCG 那台机器能访问到的地址**（如 `http://10.0.0.5:3000`，不能填 localhost）
- [ ] 设置输出：PGM 默认通道 1 层 20；需要 PVW 监看时启用 PVW 那一路（默认通道 2 层 20）
- [ ] 保存后，顶栏应显示「CasparCG 已连接 · 已加载 N 路」，设备页显示 CasparCG 版本号
- [ ] 做主备时：**先把主备配好再加载 CasparCG 输出**（或配好后点一次「重连」），这样 CasparCG 加载的地址才带 `&failover=` 备机地址
- [ ] **验收**：
  - [ ] 切换台上 Key 信号干净：图文边缘没有黑边 / 白边，半透明面板透出底下画面
  - [ ] 播出单里每个模板都在 PGM 上过一遍（见 3.4）
  - [ ] 在 CasparCG 服务器上重启 CasparCG，LiveCG 自动重连并重新加载输出（控制台状态先变「连接中」再回到「已连接」）

### 3.3 OBS / vMix（用浏览器源时）

- [ ] 从「房间」页复制该房间的 PGM 输出地址（主备、输出令牌参数会自动带上），不要手写
- [ ] OBS：添加「浏览器」源，宽 1920、高 1080；**关闭**「不可见时关闭源」和「场景激活时刷新浏览器」（刷新会让在屏图文重播入场）
- [ ] vMix：添加 Web Browser 输入，1920×1080，确认透明通道生效
- [ ] **验收**：同 3.2 的画面检查

### 3.4 模板逐个过画面

在 PGM 监视器上逐个上屏 / 下屏，检查入场、出场动画流畅，画面在安全区内（PVW 监视器带安全框）：

- [ ] 比分条（CS2） · 选手血量 / 经济 · 击杀信息 · 回合结算
- [ ] 人名条 · 实时字幕（在播时修改文字，确认只换字不重播入场）
- [ ] 足球比分条 · 篮球比分条 · 比赛事件 · 首发名单
- [ ] 同一图层连续换两条人名条：先出场再入场，不叠在一起
- [ ] 「外观」换一个主题再换回默认：在屏图文立即换色，不重播入场

## 4. CS2 数据接入

- [ ] 把 `integrations/cs2/gamestate_integration_livecg.cfg` 复制到 OB 机的 `game/csgo/cfg/` 目录
- [ ] 修改 `uri` 为 `http://10.0.0.5:3000/gsi/cs2/<房间标识>`（房间卡片上可复制），`token` 与 `CS2_GSI_TOKEN` 一致
- [ ] 做主备时：再放一份 `gamestate_integration_livecg_backup.cfg`，`uri` 改成备机地址（备机接管前会忽略这些数据）
- [ ] 联调期间打开录制：`.env` 里 `LIVECG_CS2_CAPTURE=1` 后重启服务。游戏推来的原始数据会存到 `<数据目录>/captures/cs2-<房间>-<日期>.jsonl`（已去掉 token），遇到问题时把这个文件发给开发，开发端用 `pnpm replay:cs2 <文件>` 原样回放复现。文件增长较快（每小时几十到几百 MB），**正式播出前关掉**
- [ ] 重启游戏，以**观察者 / OB 身份**进入比赛（只有观察者客户端才有全部选手的数据）
- [ ] 控制台「CS2」页：「最近数据」在几秒以内，地图、回合、阶段正确
- [ ] **验收**：
  - [ ] 比分、回合号与游戏内一致（重点核对回合结束那一刻的回合号）
  - [ ] **半场换边后**，比分条上主队仍在左边、比分没有对调；主队阵营从 CT 变为 T（或反之）
  - [ ] 击杀信息与游戏内一致；同一时刻多人阵亡时，记录击杀者 / 被杀者配对是否正确
  - [ ] 回合结束自动弹出回合结算，下一回合开始自动下屏
  - [ ] 有加时赛时，加时换边后主客队仍然正确
  - [ ] **数据延迟**：量出直播信号相对游戏的延迟，填到「数据延迟 (ms)」，确认击杀信息与画面里的击杀同时出现

## 5. 场馆计分器接入（传统体育）

- [ ] 拿到计分器型号和协议文档，桥接程序按 README「接入场馆计分器」的格式发 UDP（JSON 或 key=value）
- [ ] 先用模拟器演练整条链路：在任意一台能连到 LiveCG 的机器上运行

  ```bash
  pnpm sim:scoreboard --host 10.0.0.5 --port 5300
  ```
- [ ] 控制台「设备 → 计分器输入」启用、端口一致；时钟来源选「计分器」
- [ ] 「赛况」页开始一场新比赛，选对赛制（足球 / 篮球 FIBA / 篮球 NBA）
- [ ] **验收**：
  - [ ] 比分、节次、全队犯规、剩余暂停与场馆大屏一致
  - [ ] 比赛时钟与场馆大屏对比 **10 分钟以上**，误差不超过 0.2 秒；停表、开表的响应没有明显滞后
  - [ ] 进攻时钟（篮球）与场馆一致；比赛时钟剩余少于进攻时钟时，进攻时钟自动隐藏
  - [ ] **掉线演练**：拔掉桥接网线 → 顶栏在设定时间（默认 3 秒）内出现红色「计分器掉线」→ 把时钟来源切回「内部时钟」→ 时钟从最后读数继续走，操作员可手动开停表 → 恢复网线后再切回「计分器」
- [ ] 足球（一般没有计分器）：手动开停表、补时、进球 / 红黄牌 / 换人记录，核对事件分钟（补时显示为 45+2'）

## 6. 主备演练（做主备时必做）

每一步记录：发现故障用时、接管用时、PGM 画面是否中断。

- [ ] **镜像检查**：在 A 上上屏几条图文、改比分；B 的控制台（只读）应同步显示，PGM 标记一致
- [ ] **计划内倒换**：在 A 的顶部横幅点「交给备机」→ B 变为主机、A 变为备机；PGM 画面不中断、不重播入场。再从 B 交回 A
- [ ] **故障切换（断电 / 拔网线，不要只是停服务）**：
  1. [ ] 让 A 直接断电或拔掉网线
  2. [ ] B 顶部在约 15 秒内变成红色「备机 · 主机失联」（断电、断网要等心跳超时；停服务这类正常断开会更快）
  3. [ ] **负责人先确认 A 确实不可用**（ping 不通、A 的控制台打不开），再在 B 上点「接管为主机」
  4. [ ] PGM 画面：接管前后在屏图文保持不动，不闪、不重播入场
  5. [ ] 操作员在 B 的控制台重新登录（登录状态不在主备间同步），继续上屏 / 下屏，PGM 正常响应
  6. [ ] CS2 / 计分器数据由 B 接收（桥接程序需要同时发给两台，或此时改发给 B）
  7. [ ] CasparCG 状态在 B 上显示「已连接」
- [ ] **原主机恢复**：A 恢复后自动以备机身份加入（顶部黄色「备机 · 同步中」），不会抢回播出；确认后用「交给备机」把播出交回 A
- [ ] **双主演练**：断开 A 与 B 之间的网络但两台都不关机，在 B 上接管 → 恢复网络后两台顶部都出现红色「双主告警」→ 在不该播出的那台上点「本机降为备机」。演练后把操作规则写进当班手册：**接管前必须先确认主机真的挂了**
- [ ] **验收**：三种切换中 PGM 画面都没有中断；记录的各项用时可以接受

- [ ] 限定了房间的账号打开别的房间：只能看，不能操作
- [ ] Stream Deck / Companion：在「我的账号」创建 API 令牌，按 README「外部控制」配置按键，逐个按键验证；吊销令牌后按键立即失效
- [ ] 「操作审计」（管理员）里能看到本次演练的操作，包括被拒绝的

- [ ] 每个要用的模板在 PVW 上过一遍

## 10. 已知限制（演练时重点留意）

- CS2：回合号的自增时机是按回合结果推断的；同一时刻多人阵亡时击杀者与被杀者的配对是推测的；加时赛换边依赖游戏的半场标记
- 篮球「最后两分钟」、足球点球大战等特殊规则没有建模，需要时手动处理
- 登录状态不在主备之间同步，切到备机需要重新登录；备机上不能修改账号
- LiveCG 没有内置 HTTPS
